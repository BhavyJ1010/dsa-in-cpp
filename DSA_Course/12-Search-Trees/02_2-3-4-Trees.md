
# 2-3-4 Trees

## 1. Introduction

A 2-3-4 Tree is a self-balancing multiway search tree.

It is an extension of a 2-3 Tree. The major difference is that a node can contain up to **three keys** and have up to **four children**.

The name comes from the possible number of children:

- 2-node: 1 key, 2 children.
- 3-node: 2 keys, 3 children.
- 4-node: 3 keys, 4 children.

## 2. Structure of Nodes

### 2-node

```text
       [20]
       /  \
      L    R
```

One key and two children.

### 3-node

```text
        [20 | 40]
       /    |    \
      L     M     R
```

Two keys and three children.

### 4-node

```text
       [20 | 40 | 60]
      /     |    |    \
     A      B    C     D
```

Three keys and four children.

For a 4-node:

- A contains keys < 20.
- B contains keys between 20 and 40.
- C contains keys between 40 and 60.
- D contains keys > 60.

All keys inside a node are maintained in sorted order.

## 3. Properties of a 2-3-4 Tree

1. Each node contains 1, 2 or 3 keys.
2. A node containing k keys has k+1 children, if it is an internal node.
3. Keys inside every node are sorted.
4. Subtrees follow the search-tree ordering property.
5. All leaf nodes are at the same level.
6. The tree remains height-balanced.

## 4. Searching

Searching works similarly to a 2-3 Tree.

At each node:

1. Compare the required key with the keys present.
2. If a match is found, the search is successful.
3. Otherwise, select the appropriate child according to the key ranges.
4. Continue until the key is found or a leaf is reached.

Example:

```text
             [20 | 40 | 60]
            /     |    |    \
           A      B    C     D
```

To search for 50:

- 50 > 20
- 50 > 40
- 50 < 60

Therefore, move to subtree C.

## 5. Insertion

A 2-3-4 Tree can contain at most three keys in a node.

Insertion is performed at a leaf, but we must handle full nodes (4-nodes).

There are two ways to explain insertion:

- Bottom-up splitting: split a node after it overflows.
- Top-down splitting: split a full node before descending into it.

We will use the top-down approach here.

### Case 1: Insertion into a non-full leaf

If the leaf contains one or two keys, insert the new key in sorted order.

Example:

```text
Before:

    [20 | 40]

Insert 30:

    [20 | 30 | 40]
```

No splitting is required.

### Case 2: Encountering a full node

Consider a full node:

```text
       [20 | 40 | 60]
```

Before descending into this node, split it.

- The middle key (40) moves to the parent.
- The left key (20) becomes a separate node.
- The right key (60) becomes another separate node.

```text
Before:

       [20 | 40 | 60]

After:

           [40]
          /    \
        [20]   [60]
```

If the full node is the root, create a new root containing the promoted key.

### Case 3: Continuing insertion

After splitting, decide which child should receive the new key.

Repeat the process while moving down the tree.

Since full nodes are split before entering them, we never descend into a full node.

Eventually, we reach a non-full leaf and insert the key.

## 6. Example of Insertion

Consider inserting:

```text
10, 20, 30, 40
```

Insert 10, 20 and 30:

```text
[10 | 20 | 30]
```

Now the root is full.

Before inserting 40, split the root:

```text
       [20]
       /  \
     [10] [30]
```

Now insert 40 into the right leaf:

```text
       [20]
       /  \
     [10] [30 | 40]
```

The tree remains balanced.

## 7. Relationship Between 2-3 Trees and 2-3-4 Trees

Both are balanced multiway search trees.

| Feature | 2-3 Tree | 2-3-4 Tree |
|---|---|---|
| Minimum keys per node | 1 | 1 |
| Maximum keys per node | 2 | 3 |
| Minimum children (internal node) | 2 | 2 |
| Maximum children | 3 | 4 |
| Leaf depth | Same | Same |
| Balance | Always balanced | Always balanced |

The 2-3-4 Tree allows one additional key and child compared with a 2-3 Tree.

## 8. Time Complexity

Because all leaves are at the same depth, the height remains logarithmic.

| Operation | Time Complexity |
|---|---|
| Search | O(log n) |
| Insertion | O(log n) |

A split takes constant time at a node, and the number of levels is logarithmic.

## 9. Key Takeaways

- A 2-3-4 Tree is a balanced multiway search tree.
- Each node can contain 1, 2 or 3 keys.
- A node with k keys has k+1 children when it is an internal node.
- Full nodes are split before descending into them in top-down insertion.
- The middle key is promoted to the parent.
- Splitting the root increases the height of the tree.
